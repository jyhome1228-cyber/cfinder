# 개발 순서

## 1단계 · 검사 흐름의 뼈대 — 구현

목표는 학생이 처음 진입한 뒤 체험 응답을 완료할 때까지 막히지 않게 하는 것입니다.

- 중학생용·고등학생용 선택과 안내
- 문항 응답, 이전·다음 이동, 미응답 확인
- 탭 내 임시 저장, 새로고침 복원, 이어하기
- 응답 검토와 수정, 완료 상태 보호
- 결과지 구성 미리보기
- 동일 검사에 기관명·색상을 적용하는 예시
- 문항·상태·저장·화면·기관 설정 분리 및 상태 검증 테스트

이 단계의 완료는 **체험 흐름의 구현**을 뜻합니다. 실제 진단을 운영할 수 있다는 뜻은 아닙니다.

코드의 정적 검사와 자동 테스트는 통과했으며, 실제 브라우저에서의 전체 흐름·모바일 시각 검증은 [수동 확인 항목](architecture.md#수동-확인-항목)으로 남아 있습니다.

## 2단계 · 승인된 검사와 결과 연결

목표는 한 학생의 응답에서 재현 가능한 진단 결과를 제공하는 것입니다.

| 작업 | 완료 조건 |
| --- | --- |
| 문항·척도 확정 | 중·고등학생용 문항, 요인 연결, 역채점, 대상, 버전을 승인 |
| 채점 규칙 확정 | 원점수·규준·RIASEC·경향성·동점·결측 규칙을 문서화 |
| 채점 검증 | 승인된 입력/기대 결과가 경계·동점 사례까지 일치 |
| 응답 API | 서버 검증, 계정 또는 참여 세션 확인, 저장·복원·중복 제출 처리 |
| 결과 API | 채점 상태와 버전, 승인된 해석·추천 내용을 반환 |
| 결과 화면 | 실제 응답의 분석과 구성 예시를 분명하게 구분하며 완성 |

착수 자료와 데이터 형식은 [검사 계약](assessment-contract.md)을 기준으로 정리합니다. 채점 규칙이 불명확한 동안에는 체험판에 실제 유형이나 점수를 붙이지 않습니다.

## 3단계 · 기관별 운영

목표는 기관이 같은 검사를 자체 프로그램 안에서 배포하고 관리하도록 지원하는 것입니다.

| 작업 | 완료 조건 |
| --- | --- |
| 기관 설정 | 기관별 이름·로고·색상·안내·주소를 운영자가 설정 |
| 참여 배포 | 기관·프로그램별 참여 링크 또는 코드로 대상자를 연결 |
| 권한 | 참여자·상담자·기관 운영자의 범위를 서버에서 확인 |
| 운영 화면 | 배포 현황, 참여·완료 현황, 허용된 개인 결과 조회 |
| 집단 리포트 | 승인된 집계 기준으로 기관별 현황과 결과 제공 |

현재의 `?org=sample`은 이 단계의 **브랜드 적용 예시**입니다. 기관 생성·접근 권한·학생 데이터 관리가 구현된 상태는 아닙니다.

## 우선순위 밖의 기능

결제, 구독 요금제, 상담 예약, 콘텐츠 마켓, 복잡한 CRM은 현재 뼈대의 범위에 포함하지 않습니다. 먼저 정식 검사 한 회의 응답·채점·결과 제공을 완성하고, 실제 운영 요구를 확인한 뒤 추가합니다.
