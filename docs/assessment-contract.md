# 검사 데이터와 결과 계약

이 문서는 현재 체험판 코드의 계약과 정식 검사 연결 전에 확정할 항목을 구분합니다. 현재 문항과 5단계 응답 척도는 화면 검토용 예시입니다.

## 1. 검사 정의

원본: [`assets/data/assessments.js`](../assets/data/assessments.js)

| 필드 | 현재 값·형식 | 의미 |
| --- | --- | --- |
| `id` | `cfinder-middle-demo`, `cfinder-high-demo` | 검사 식별자 |
| `version` | `demo-1` | 검사 정의 버전 |
| `mode` | `demo` | 체험 검사임을 표시 |
| `grade` | `middle` 또는 `high` | 대상 구분 |
| `label` | 표시용 문자열 | 중학생용·고등학생용 이름 |
| `description` | 표시용 문자열 | 선택 화면 설명 |
| `options` | `{ value: 정수, label: 문자열 }[]` | 선택 가능한 응답 값과 표시 이름 |
| `questions` | `{ id, domain, text }[]` | 문항 목록; ID는 검사 안에서 고유 |

`domain`은 현재 `interest`, `aptitude`, `values` 중 하나입니다. UI의 영역 설명은 `DOMAINS`에서 가져옵니다. 문항 수는 배열에서 계산하며 화면에 별도 상수를 두지 않습니다.

## 2. 응답 상태

원본: [`assets/core/assessment.js`](../assets/core/assessment.js)

| 필드 | 형식 | 의미 |
| --- | --- | --- |
| `schemaVersion` | `2` | 저장 형식 버전 |
| `tenantId` | 문자열 | 현재 기관 설정의 식별자 |
| `assessmentId` | 문자열 | 검사 ID |
| `assessmentVersion` | 문자열 | 검사 정의 버전 |
| `grade` | `middle` 또는 `high` | 대상 구분 |
| `status` | `in_progress` 또는 `completed` | 진행 상태 |
| `answers` | 문항 ID를 키로 하는 객체 | 선택한 정수 응답 값 |
| `currentIndex` | 0부터 시작하는 정수 | 마지막으로 방문·응답한 문항 위치 |
| `startedAt` | UTC ISO 문자열 | 응답 시작 시간 |
| `completedAt` | UTC ISO 문자열 또는 `null` | 완료 시간 |

응답 변경 함수는 기존 객체를 직접 수정하지 않고 새 객체를 반환합니다. 문항 ID와 응답 값은 해당 검사 정의에 속해야 합니다. 모든 문항에 응답해야 완료할 수 있으며, 완료 후 응답 변경은 거절합니다.

화면 경로의 `grade=middle`·`grade=high`는 어느 학교급의 저장 상태를 열지 식별합니다. 실제 `answers`는 URL에 포함하지 않습니다. 브라우저 이동 기록을 복원할 때도 해당 학교급의 응답을 사용합니다.

`restoreAttempt()`에는 JSON 파싱을 마친 객체를 전달합니다. 기관·검사·버전·학년·스키마가 다르면 `null`을 반환합니다. 알 수 없는 응답은 제거하고, 잘못된 위치는 보정합니다. 완료로 저장되어 있어도 응답이나 완료 시간이 유효하지 않으면 `in_progress`로 복원합니다. 브라우저 상태는 사용자가 변경할 수 있으므로 정식 서비스의 권위 있는 검사 기록으로 사용하지 않습니다.

## 3. 현재 결과 응답

원본: [`assets/services/results.js`](../assets/services/results.js)

```json
{
  "status": "demo-completed",
  "assessmentId": "cfinder-middle-demo",
  "assessmentVersion": "demo-1",
  "answeredCount": 3,
  "completedAt": "<완료 시각>",
  "scores": null,
  "careerType": null,
  "recommendations": []
}
```

`getResultSummary()`는 완료한 동일 검사에 대해서만 응답합니다. 정식 검사 모드를 넘기면 승인된 서버 채점 제공자가 필요하다는 오류를 반환합니다. 화면용 체험 데이터를 실제 점수·유형·추천으로 바꾸는 우회 계산은 두지 않습니다. 결과지 미리보기는 결과의 구성을 설명하는 화면이며 개인 응답에서 산출한 분석이 아닙니다.

## 4. 정식 검사 연결에 필요한 승인 항목

| 묶음 | 확정할 내용 |
| --- | --- |
| 문항 | 중·고등 원문, 고유 ID, 제시 순서, 영역·하위요인 연결, 필수 여부 |
| 척도 | 허용 응답 값, 표시 문구, 역채점 대상과 변환 규칙 |
| 검사 버전 | 문항·척도·대상 변경 시 버전 규칙, 기존 응답 처리 방식 |
| 점수 | 원점수 산식, 가중치, 결측 처리, 표준화·규준 변환, 반올림 |
| 유형 | RIASEC 결과 코드 산출, 복합 유형 선정, 동점·경계 처리 |
| 경향성 | 중복 특성 집계 방식, 우선순위, 동점 처리, 임계값의 기준 점수 |
| 해석 | 일관성·변별성 등 지표의 산식과 표현 기준 |
| 추천 | 결과 코드와 승인된 설명·직업·활동의 연결 관계 |
| 검증 | 연구팀이 확인한 입력 응답과 기대 결과의 묶음 |

기획 자료에 언급된 **흥미 27개·적성 13개·가치관 9개는 요인 수**입니다. 총 문항 수나 검사 시간으로 바꾸어 사용하지 않습니다. 현재 제공된 정보만으로 공식 문항 전체와 최종 채점식을 확정하지 않습니다.

특히 경향성 자료의 중복 특성 가중치가 문항·요인별로 누적되는지, 특성별로 한 번 적용되는지와 동점·임계값의 기준을 확인해야 합니다. 예시에서 추측한 규칙을 운영 코드로 고정하지 말고 연구팀의 승인된 기대 결과로 검증합니다.

## 5. 서버 연결 시 유지할 원칙

- 검사 정의, 채점 규칙, 결과 문구의 버전을 각각 기록하여 결과를 재현할 수 있게 합니다.
- 서버가 문항·응답·기관 접근 권한을 다시 검증하고, 같은 제출의 재시도로 기록이 중복되지 않게 합니다.
- 결과에는 사용한 버전과 처리 상태를 포함하고, 계산 중·실패·재시도를 화면에서 구분합니다.
- 기관의 브랜딩 설정은 검사 데이터나 채점 규칙을 바꾸지 않습니다. 승인된 검사 변형은 별도 검사·버전으로 관리합니다.
- 비공개 연구 자료와 실제 응답을 공개 프런트엔드 저장소에 넣지 않습니다.

## 49개 요인 자기탐색 확장 (2026-11-24)

현재 중·고등학생용 `assessment.kind === 'factor_exploration'`은 `mode:'demo'`, `formal:false`인 **비공식 콘텐츠 탐색**입니다. 정식 문항 뱅크는 제공되지 않았습니다. 49개 문장을 요인명/의미로부터 제작했으며 5단계 자기보고 응답만 수집합니다. 완료 시 사용자 응답 4·5를 표시할 뿐 원점수·규준·RIASEC 두 글자 코드·추천 직업을 산출하지 않습니다. 대학생용은 3문항 데모입니다. 위 확장은 공식 심리검사 구현과 분리해 유지해야 합니다.
